Findings C — Critical: blocks core workflow

C1 · Recipe ingredient picker is a plain dropdown with 30+ options Critical DONE

The ingredient selector in the recipe form is a standard <select> with all ingredients listed. With 33+ ingredients, finding the right one requires scrolling through a long list. No search, no filtering, no typeahead. The template renders a <template> for new rows with the same problem.

templates/recipes/form.html:99-103 (ingredient select) · app.js (dynamic row JS).

Recommend: Replace with a searchable select (e.g., Select2 or a native <datalist>). Or group ingredients by category in the dropdown with <optgroup>. At minimum, add size and alphabetical grouping by category.

C2 · Meal plan rules require understanding 5 concepts before generating Critical DONE

To generate a meal plan, the user must: (1) understand day-of-week syntax (mon,wed,fri or weekday/weekend/all), (2) understand meal types (breakfast, lunch, dinner, snack), (3) understand tag filters (optional, comma-separated), (4) understand servings override, (5) understand priority ordering (sort_order). The "How rules work" section is collapsed by default. New users cannot generate a plan without studying the rules system first.

templates/meal_plan/view.html:182-320 (rules tab) · services/plan_generator.py.

Recommend: Add a "Quick start" that generates a plan with zero rules using a simple default ("fill every dinner slot with a random recipe"). Provide a wizard: "What do you eat for dinner?" → tag selector → done. Or: auto-generate a starter rule set from existing recipe tags.

C3 · No duplicate detection when adding ingredients Critical DONE

The ingredient form allows adding the same ingredient name multiple times. There's no unique constraint on \`name\` in the schema and no check in the route. With 33 seeded ingredients plus manual additions, duplicates are likely. The API dedupes by name, but the UI does not.

routes/ingredients.py:77-94 (ingredient_add) · database.py:63 (ingredients table, no UNIQUE on name).

Recommend: Add a UNIQUE constraint on \`name\` (migration) and check before insert in the route. Show "Ingredient already exists" with a link to edit the existing one. Also dedupe in the UI by checking on blur.

Findings H — High: significant friction

H1 · Settings page is one very long page with 6 cards High DONE

All settings (plan dates, preferences, bank imports, budget, API keys, admin) are on a single scrolling page. Finding "Monthly grocery budget" requires scrolling past 4 unrelated cards. The page is ~245 lines of template.

templates/settings.html (245 lines) · routes/settings.py (260 lines).

Recommend: Split into tabs: General (dates + prefs), Bank (bank imports + API keys), Budget, Admin. Or use <details> sections (already used elsewhere in the app) to collapse each card. Keep the current single-page for simplicity but add anchor links / a sidebar TOC.

H2 · Products linking has no auto-suggest for 450+ products High DONE

The products page lists 450+ purchased products, each requiring manual ingredient selection from a dropdown. No fuzzy matching, no "suggest by name similarity", no bulk auto-link. The "Save all links" button was removed during the HTMX conversion (now individual saves only). Manual linking of 450 products is impractical.

templates/spend/products.html · routes/spend.py:spend_link_product, spend_link_batch.

Recommend: Add a "suggest" button that auto-links products to ingredients by name similarity (e.g., "Woolworths Free From Lactose Milk" → "Milk (Lactose Free, Full Cream)"). Show suggestions as a preview, let the user accept/reject. Restore the "Save all" button for batch operations.

H3 · Ingredient form has 9 fields — overwhelming High DONE

The ingredient form requires: name, display_name, category, unit, price, URL, store, minimum_stock, pack_size. Most users only need name + category + unit + price. The rest (display_name, URL, store, min stock, pack size) are advanced fields that should be collapsed or auto-filled.

templates/ingredients/form.html · routes/ingredients.py:_read_form().

Recommend: Show only name, category, unit, price by default. Collapse the rest under "Advanced" (details/summary, consistent with the app's pattern). Auto-populate display_name from name. Auto-populate store from the most recent purchase.

H4 · Navigation has 9 items — no grouping High DONE

The top nav lists: Dashboard, Ingredients, Recipes, Meal Plan, Shopping List, Pantry, Spend, Bills. That's 8-9 items in a single horizontal bar. On mobile, the bottom nav shows 5-6. There's no grouping (e.g., "Plan" group vs "Track" group) and no active-state highlighting beyond the current page.

templates/base.html:25-34 (nav_items) · base.html:110-120 (bottom nav).

Recommend: Group nav into 3 sections: Plan (Meal Plan, Recipes, Ingredients), Shop (Shopping List, Pantry), Track (Spend, Bills). Use a dropdown or sidebar on desktop. Highlight the active section. On mobile, keep the 5 most-used in the bottom bar.

H5 · No global search High DONE

Search exists only on the ingredients list page. There's no way to search across recipes, products, and ingredients simultaneously. A user who remembers "I bought salami last week" has to navigate to Spend → Products → search. A user who wants "recipes with chicken" has to go to Recipes → filter by tag.

templates/ingredients/list.html (search form) · templates/recipes/list.html (search form) · templates/spend/products.html (search form).

Recommend: Add a global search bar in the navbar (or Cmd+K shortcut) that searches across ingredients, recipes, and products. Show results grouped by type. This is the single biggest discoverability improvement.

H6 · Spend dashboard empty state is buried High DONE

When there are no purchases, the "Import purchases" CTA is at the bottom of the page (line 42), below a large "No purchase history yet" alert. New users see an empty dashboard first and have to scroll to find the import button.

templates/spend/dashboard.html:39-44.

Recommend: Move the import CTA to the top of the empty state, as a prominent button. Or redirect new users to the import page on first visit.

Findings M — Medium: friction and mistrust

M1 · Pantry "Use" flow requires typing an amount Medium DONE

Consuming pantry stock requires typing a number into a form field. There's no "use all" button, no "use one serving" shortcut, and no quick-tap for common amounts. On mobile, this means opening the keyboard for every consume action.

templates/pantry/list.html:82-87 (consume form) · routes/pantry.py:pantry_consume.

Recommend: Add a "Use all" button next to the form. Add quick-pick buttons for common amounts (1, 2, 5 units). Or: when the recipe is cooked, auto-consume the recipe's ingredient quantities from pantry.

M2 · No recipe scaling Medium DONE

Recipes have a fixed servings count. There's no way to view a recipe scaled to a different number of servings. The meal plan allows per-entry servings override, but the recipe detail page doesn't show scaled quantities.

templates/recipes/detail.html · models.py (no scaling function).

Recommend: Add a servings scaler on the recipe detail page: "Scale to N servings" → recalculates all ingredient quantities. This is a common recipe-app expectation.

M3 · No undo for deletes Medium DONE

All delete actions (ingredient, recipe, pantry item, shopping list item, subscription) are immediate with only a JavaScript confirm dialog. There's no soft delete, no undo, no "recently deleted" recovery. A misclick on "Delete" with a slow mouse is permanent data loss.

routes/ingredients.py:133-140 · routes/recipes.py · routes/pantry.py:115-122.

Recommend: Add a 5-second "Undo" toast after delete (HTMX makes this easy: swap the row with an undo button, then actually delete after 5s). Or: soft-delete (active=0) for ingredients/recipes, matching the subscription pattern.

M4 · Shopping list cost estimates are misleading until products are linked Medium DONE

The shopping list shows estimated costs based on ingredient prices (manually entered or from linked products). Until products are linked, estimates use placeholder prices (often $0 or stale). The "Estimated till total" card shows a number that may be far from reality.

services/shopping_list_generator.py · templates/shopping_lists/view.html:42-54.

Recommend: Show a "prices not linked" badge next to the estimate when any ingredient lacks a linked product. Add a "Link products →" CTA. Make the estimate card collapse or show "—" when no prices are set.

M5 · Empty states are inconsistent Medium DONE

Some empty states have CTAs (ingredients: "Add your first ingredient"), some have plain text (recipes: "No recipes found. Add your first recipe"), some have alerts (spend: "No purchase history yet."). Styling varies: some use alert-info, some use alert-secondary, some use plain <p>.

templates/ingredients/list.html:74-82 · templates/recipes/list.html:73-78 · templates/spend/dashboard.html:39-44.

Recommend: Create a shared empty-state partial (_empty_state.html) with consistent styling: icon + message + CTA button. Use it everywhere.

M6 · Inconsistent verbs for pantry actions Medium DONE

The pantry uses "Use" (consume), "Add" (stock), and "Delete" (remove). The shopping list uses "Tick" (mark bought). Subscriptions use "Mark paid", "Pause", "Delete". No consistent verb set across features for the same concept (remove vs delete vs purge).

templates/pantry/list.html · templates/subscriptions/list.html · templates/shopping_lists/view.html.

Recommend: Standardise: "Remove" for soft-delete, "Delete" for permanent, "Use" for consume, "Mark done" for tick. Document in a style guide.

M7 · No breadcrumbs on deep pages Medium DONE

Pages like recipe edit, ingredient edit, and meal plan rules have no breadcrumb trail. Users can't easily navigate back to the parent list. The only way back is the browser back button or the nav bar.

templates/recipes/form.html · templates/ingredients/form.html · templates/meal_plan/view.html.

Recommend: Add a simple breadcrumb: "Ingredients / Edit: Milk". Use the existing page-head or a small <nav aria-label="breadcrumb"> component.

Findings L — Low polish

L1 · No keyboard shortcuts Low DONE

Power users have no keyboard shortcuts for common actions (add ingredient, generate plan, tick item). The app is mouse-driven throughout.

static/js/app.js (minimal).

Recommend: Add Cmd/Ctrl+K for global search (once H5 is built), and single-key shortcuts for the most common action per page (e.g., 'n' for new). Low priority.

L2 · No recipe image upload — URL only Low DONE

Recipe images require a URL. Users can't upload a photo from their phone. The form has a URL input only.

templates/recipes/form.html:60-77.

Recommend: Add a file upload option alongside the URL input. Store in /app/data/images/ and serve via a static route. Medium effort, high delight.

L3 · No recipe rating or favorites Low DONE

Recipes have no rating, favorite, or "last cooked" field. Users can't mark frequently-used recipes or filter by favorites.

database.py (recipes table) · templates/recipes/list.html.

Recommend: Add a simple "favorite" star toggle on recipe cards. Filter by favorites. Track "last cooked" date from meal plan entries.

L4 · Shopping list print layout could be better Low DONE

The print view hides interactive elements (d-print-none) but the table layout and spacing could be tighter for a printed shopping list. No print-specific CSS.

templates/shopping_lists/view.html · static/css/style.css.

Recommend: Add a @media print stylesheet: remove card borders, tighten row spacing, show only essential columns (name, qty, unit, tick box).

What's working (don't regress)

Getting started checklist on dashboard

The 5-step onboarding checklist with muted completed steps is the best onboarding in the app. Clear, actionable, progressive.

Empty states with next actions (round 2)

Subscriptions and Suggestions pages explain the void and link the fix. Hold this as the template for all empty states.

HTMX async updates (round 3)

Shopping list tick, pantry consume, subscription actions all update in place. No page reloads. The progressive enhancement pattern (works without JS) is excellent.

API key show-once + prefix + last-used

Correct secrets UX. Full key displayed once, table keeps identifying prefix, last-used timestamps.

Inline errors on forms

Recipe and ingredient forms re-render with typed values and inline error messages. The B1 pattern from round 1 is applied consistently.

Spend dashboard KPI tiles

Clear, scannable, with trend indicators and sparklines. The budget tile with pace projection is excellent.

Roadmap (impact first, shippable slices)

  1. Make the core workflow faster. C1 (searchable ingredient picker) + C2 (simplified meal plan generation). These two changes make the app usable for non-technical users.
  2. Reduce form friction. H3 (collapse advanced ingredient fields) + H1 (tabbed settings). Less scrolling, fewer fields.
  3. Improve discoverability. H5 (global search) + H4 (grouped nav). Users find things faster.
  4. Fix empty states and onboarding. M5 (consistent empty states) + H6 (spend empty state CTA). Better first-run experience.
  5. Polish. M1 (pantry use shortcuts) + M2 (recipe scaling) + L2 (image upload). Delight features.
